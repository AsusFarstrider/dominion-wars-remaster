# Adaptive launch output: concrete source review

2026-10-30. Reviewed `dynamic-output-work-01` against accepted `esc-menu-perf-source-v1`. **The initial cross-subsystem startup blocker was corrected during review; no additional bounded source blocker identified in the pinned revision.** Engine ran no build, fixture or game. This is not cold-start, fitted-media or arbitrary-display acceptance.

**Corrected blocker:** OpeningFlow::installSafety still required the fixed DE3 executable while native-display-v1 required neutral E81. DllMain would therefore install the entry detour, then refuse static loading before the bridge ran. The corrected source selects validated managed config.engine; Options allows E81 only for native-display-v1 and DE3 for native-1440-v1. Unmanaged research still requires DE3; codec/asset checks remain. The startup fixture bypasses this configuration/DllMain chain, so its success alone would not have caught the rejection. Rendering owns a focused admission check and rebuilding after the correction.

**Entry installation:** OutputMode validates static load, mapped base, PE machine/entry and the exact five-byte prologue. A private32-byte trampoline is allocated RW, populated with the three original instructions plus return jump, made RX and flushed before entry modification. rel32 uses checked int64 arithmetic. The actual target and trampoline are read back, protection/flush failures reject installation, and a possibly referenced trampoline is retained on a post-write failure. DllMain returnsFALSE; the original CRT must never run after partial admission. The exact disk hash established by Remaster::load supplies the stronger PE identity; the install helper is not a general untrusted-PE parser.

The naked bridge saves GPRs/flags, an aligned512-byte FXSAVE state and its original stack pointer, initializes x87 for the binder, then restores FP/SSE state, stack, registers and flags and jumps through the trampoline. LastError is preserved by the binder. The existing wrapper requires SSE2. The binder uses DLL-side state after DLL initialization, without invoking engine/EXE CRT subsystems or DirectDraw. No new executable section, import/export or disk rewrite is introduced.

**Operand transaction:** canonical launch strings are parsed as one bounded W/H pair; physical primary mode/origin must match. All15 complete expected instructions are checked before writes. All involved pages become writable before any operand changes, with individual prior protections retained. Seven W/H pairs and calibrated base m11 use the same selected size. Flush/protection/readback failures returnfalse and the caller exits before jumping to original CRT. Session/bound are published only after success. This is an all-or-stop startup contract, not rollback that permits continuing after a failed write. The15 table entries match the earlier original/control map; HUD projection correction is unchanged.

**Integration:** disk identity remains exact, while NativeProbe copies the allowlisted engine record and substitutes the bound runtime W/H for selected-mode validation. It still rejects selected dimensions before original mode application. MenuProbe admits the neutral engine only through a valid managed dynamic profile and retains exact hook-byte guards. Runtime requires bound dimensions before functional initialization. Esc CanvasRuntime, OrderedPaint performance repair and HUD source are unchanged from the accepted parent.

One configuration dependency remains explicit: OutputMode uses EnumDisplaySettingsExW directly, and Runtime uses EnumDisplaySettingsW. DDrawCompat can virtualize those APIs if display hooks are installed early; default DesktopResolution=desktop avoids its optional attach-time display-hook/worker path. Keep the isolated profile's physical-query assumption enforced, or deliberately use original API semantics. Do not treat a match against virtualized dimensions as independent physical-monitor proof. Phase1 stays primary-origin0; temporary1080-as-primary avoids changing the input-control body.

**HD output:** HdHistory retains original source W/H, pitch, storage guards, first-full/selective conversion rules, result semantics, seek reset and quarantine. Its new present method uses identity rows when dimensions match, otherwise caches Plan::fit(source,target) and composes directly into the valid target lease, clearing margins. No800×600 intermediate or resized decoder history is introduced. Source profile2560×1440 remains an asset condition. Copy, successful Unlock and root input admission now use committed targetW/H together, while retaining movie lifetime/owner/epoch/lease checks. Whole-output skip behavior is preserved. Scaled provenance is set before presentation, including allocation failure; exceptions quarantine and withhold publication. Raw source/target pixel hashes are restricted to identity output; nonidentity fitted pixels are not certified by those receipts.

**Fixture limits:** the inspected OutputModeTests exercises installer/binder/naked bridge and fault injection against owned synthetic PE pages, with eight simulated sizes. The host could not reserve400000; the revised fixture mechanically relocates only base/entry/site literals and local includes to20000000. Engine checked that transformation against production source without compiling or running it. This tests relocated control logic, not the production400000 loader transfer or complete managed startup. The fixture stubs note and forces managed/valid/profile flags; it does not execute Remaster::load, OpeningFlow::installSafety, original CRT constructors, mode enumeration or a real Bink decode. Initial reservation/OS relocation restriction is a fixture limitation, not a game failure. Execution receipts and clean build after the final change remain Rendering's responsibility.

Bounded remaining validation is the already-planned prototype scope: managed admission, real cold entry at the production base, actual selected/created sizes, HD fitting/skip publication, menus/HUD/world input and before/after-mission behavior using the same binary. Eight fixture sizes do not imply eight real-display passes. No extra reconstruction campaign, nonprimary input rewrite or live resizing is requested. Current, accepted fixes and release remain untouched; Master integration is separate.
