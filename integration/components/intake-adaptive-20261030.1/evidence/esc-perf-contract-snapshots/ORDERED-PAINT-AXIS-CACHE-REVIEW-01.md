# Ordered foreground axis cache: bounded source review

2026-10-29. Reviewed `esc-menu-perf-work-01` against frozen `esc-main-menu-source-v1`. **No bounded source blocker identified.** Engine ran no build, fixture, benchmark or game. This reviews the replay optimization, not live cursor responsiveness or release acceptance.

The original `Canvas::inverse_pixel` tests content membership then independently searches rounded x and y edges. For the admitted zero-origin800×600 logical canvas, caching x from `(x,content.top)` and y from `(content.left,y)` therefore produces exactly the same logical cell as the old per-pixel query. No approximate scale, center sampling or new rounding rule is introduced. The raw rectangle, mask/color index, operation order, sprite sampling/blending, clipping and write count remain unchanged.

`validView` bounds destination extents to16384 each and checks storage/pitch/address arithmetic. The output-bounds equality guard fixes the origin at zero; a fitted Canvas keeps its content inside that output. Cached logical coordinates fit uint16_t (x0..799/y0..599). Every mapped operation lies inside initialized content rows/columns; letterbox entries are never read. The production caller passes a `MenuCanvas::Plan` geometry, whose factory rejects empty rounded content. A standalone degenerate Canvas with empty content can now fail earlier than the former no-op replay; it is outside that production path.

The two arrays are compose-local `unique_ptr<uint16_t[]>`, allocated only when raw operations exist. Their maximum combined payload is65536 bytes (8000 bytes at2560×1440). Bounds prevent array-length overflow; `new(std::nothrow)` returns null on allocation failure, both owners clean up on all exits, and the map construction uses noexcept Canvas operations. No persistent cache, mutable shared state, borrowed surface pointer or changed sprite ownership is introduced. Sprite-only replay avoids these allocations. Repeated allocations remain a performance tradeoff; no persistent-cache redesign is required for this bounded fix.

Allocation or map-construction failure precedes **OrderedPaint foreground writes**. It does not imply an untouched whole frame: `MainBackdrop::compose` sets `nativeWritten` and paints the underlay before calling this routine. Preserve its existing native-write/fallback protection and require successful composition before publishing mapped input. This change leaves those mechanisms intact.

Rendering reports Preferences-only cursor lag and a synthetic CPU-only baseline of about217ms for a400×450 raw panel versus36ms for six sprites. This is consistent with repeated per-pixel binary searches; it is not measured gameplay timing, nor proof that this is the only latency source. The cache reduces inverse queries from per raw output pixel to per content row/column, without optimizing sprite blending.

Rendering owns differential whole-buffer comparison against the old routine, fractional and downscaled geometry, clipped/keyed/overlapping raw and sprite order, write counts and padding checks, benchmark/build and any focused live retry. Those results were pending at this review. The earlier Esc-only frozen candidate remains separate; no original callback, executable, input policy or Current change is reviewed here. Source pins are in `evidence/ordered-paint-axis-cache-review-01/receipt.json`.
